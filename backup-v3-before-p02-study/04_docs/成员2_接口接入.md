# 成员2的播放器接入说明

自定义手势 v3 演示页实现了静态手型、短动态示范、重绑定、录像分析、轨迹回放和三张演示卡片。接入完整网页播放器时将事件分发到实际的上一页和下一页处理器。建议从 `01_code/custom-gestures/demo.mjs` 查看启动、停止、错误和导出路径。

## 从追踪到播放器

```js
import {createTracker, watchVideo} from './tracker.mjs';
import {createRecognizer} from './custom-gestures/recognizer.mjs';
import {createActionDispatcher} from './custom-gestures/actions.mjs';

// 每次开始一个新源执行一遍。true 仅用于源像素已被镜像的录像。
const tracker = await createTracker({sourceMirrored: false, handMode: 'single'});
const recognizer = createRecognizer(profile);
const dispatcher = createActionDispatcher({
  nextPage: () => player.next(),
  previousPage: () => player.previous(),
  onEnabledChange: enabled => updateGestureControlBadge(enabled),
});
const cancel = watchVideo(video, tracker, frame => {
  frames.push(frame);
  const result = recognizer.push(frame);
  if (result?.rejection) rejections.push(result.rejection);
  if (result?.event) {
    const actionResult = dispatcher.dispatch(result.event);
    events.push({...result.event, actionResult});
  }
}, onTrackingError);

// 停止、源切换或出错时关闭，摄像头还要停止 stream 的全部 tracks。
function stopWatching() {
  cancel();
  tracker.close();
}
```

`video` 绑定浏览器摄像头流后播放，离线文件用 `scanVideo` 按固定 30 fps 采样。上传摄像头原始录像时保持源像素的镜像设置。预览可用 CSS 镜像，`frame.hand` 已经是身体右侧坐标，请直接传给识别器。媒体时间 `tMs` 必须严格递增，未能选中唯一一只手时仍传 `hand: null`。运行页、直播源、文件源、回放的完整资源释放与导出做法见 `demo.mjs`。

追踪器自动选取唯一检测到的手，`side` 作为诊断元数据。静态手型用归一化的指关节和指尖特征做按类近邻比较，默认保持约 250 ms 后可触发，明显松开或离开画面后可再触发。动态手势用掌心位移与手指形状变化组成的 20 点序列作 DTW 比较，默认接纳约 125–1600 ms 的片段，动作结束通常等待约 140 ms 的停稳。手在动作后离开画面时需要较强的匹配和足够动作幅度才会补判。类内反例与类间歧义均可拒绝，已接受的动态动作不会因保持结束手型再触发静态类别。

分发器从启用状态开始。收到 `toggle_gesture_control` 时切换状态；暂停期间下一页和上一页仍被识别并记录 `paused`。播放器在边界可以返回 `false`，分发器记录 `page_boundary`。空绑定用 `null`，记录 `unbound`。其余已分发事件记录 `executed`。需要测端到端延迟时，由播放器另行记录呈现时刻及其时间基准。

## 数据字段

| 对象 | 主要字段 |
| --- | --- |
| profile | `version: 3`、`engineVersion: 'pose-knn-motion-dtw-v3'`、`featureVersion: 'joint-shape-path-v1'`、`trackerVersion: 'single-hand-v5'`、`coordinateSystem: 'body-right-v1'`、`participantId`、`revisionId`、`parentRevisionId`、`settings`、`gestures`、`history` |
| gestures 条目 | `gestureId`、`name`、`type`（`static` 或 `dynamic`）、`actionId`、`positives`、`negatives`、`settings`。类别设置为 `threshold` 和 `negativeMargin` |
| 样例 | `sampleId`、`frames`、`confirmation`、`source`。来源记录 `runId`、类型、媒体起止及已知镜像状态，人工复核还保存对应意图或事件 |
| event | `gestureId`、`gestureName`、`gestureType`、`actionId`、`tMs`、`startMs`、`endMs`、`positiveDistance`、`negativeDistance`、`distanceMetric`、`completion`、`scores`、`frames`。播放器可附加 `actionResult` |
| rejection | `tMs`、候选起止、`reason` 和可用的各类 `scores`。没有形成候选的静止帧不会逐条写拒绝 |
| run | `version: 3`、实际 `profile` 和版本信息、`runId`、`source`、`mode`、`frames`、`events`、`rejections`。`capture` 模式仅采集，`recognition` 模式运行识别 |

`event.tMs` 是系统作出判定时的媒体时间，通常晚于候选结尾 `endMs`。候选起止供人工复核使用。静态距离和动态 DTW 距离各自表示特征差异，使用独立的阈值。导出必须保留运行时的实际参数与绑定。修改配置后要开启新一轮识别，为旧轮继续保留原快照。相同轨迹的离线回放可调用 `replay(frames, profile)`。

注册时调用 `prepareExample(frames, gesture.type, profile.settings)` 提取示范片段，再用 `createExample(clip, source)` 保存来源。静态示范取结束前的稳定手型。短动态示范需要一次连续动作。

v1 接口由 `development-v41/recognizer-development.mjs` 提供，P01 配置及原有事件按 4.1 流程复现。v3 的 `importProfile` 可升级 v2 动态模板，保留样例与绑定，用 v3 默认距离参数重新编译。`readTrajectory` 接受已导出的 `right-hand-v4` 和 `single-hand-v5` 轨迹。
