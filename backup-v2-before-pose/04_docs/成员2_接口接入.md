# 成员2的播放器接入说明

自定义手势 v2 演示页实现了注册、重绑定、录像分析、轨迹回放和三张演示卡片。接入完整网页播放器时将事件分发到实际的上一页和下一页处理器。建议从 `01_code/custom-gestures/demo.mjs` 查看启动、停止、错误和导出路径。

## 从追踪到播放器

```js
import {createTracker, watchVideo} from './tracker.mjs';
import {createRecognizer} from './custom-gestures/recognizer.mjs';
import {createActionDispatcher} from './custom-gestures/actions.mjs';

// 每次开始一个新源执行一遍。true 仅用于源像素已被镜像的录像。
const tracker = await createTracker({sourceMirrored: false});
const recognizer = createRecognizer(profile);
const dispatcher = createActionDispatcher({
  nextPage: () => player.next(),
  previousPage: () => player.previous(),
  onEnabledChange: enabled => updateGestureControlBadge(enabled),
});
const cancel = watchVideo(video, tracker, frame => {
  frames.push(frame);
  const result = recognizer.push(frame);
  if (result?.rejection) rejections.push(result.rejection);
  if (result?.event) {
    const actionResult = dispatcher.dispatch(result.event);
    events.push({...result.event, actionResult});
  }
}, onTrackingError);

// 停止、源切换或出错时关闭，摄像头还要停止 stream 的全部 tracks。
function stopWatching() {
  cancel();
  tracker.close();
}
```

`video` 绑定浏览器摄像头流后播放，离线文件用 `scanVideo` 按固定 30 fps 采样。上传摄像头原始录像时保持源像素的镜像设置。预览可用 CSS 镜像，`frame.hand` 已经是身体右侧坐标，请直接传给识别器。媒体时间 `tMs` 必须严格递增，未可靠选中右手时仍传 `hand: null`。运行页、直播源、文件源、回放的完整资源释放与导出做法见 `demo.mjs`。

识别器在手掌停稳后输出一个完整动作的判定。休止超过默认 230 ms 后可开始下一次，长追踪中断会取消尚未判定的片段。类别由带符号的二维手掌中心轨迹经尺度归一化、20 点重采样后用 DTW 匹配。默认只处理约 240–1500 ms 内达到幅度门槛的片段，类内反例可否决本类，达不到阈值或两个合格类别距离过近会拒绝。建议真人演示时动作后停约半秒。

分发器从启用状态开始。收到 `toggle_gesture_control` 时切换状态；暂停期间下一页和上一页仍被识别并记录 `paused`。播放器在边界可以返回 `false`，分发器记录 `page_boundary`。空绑定用 `null`，记录 `unbound`。其余已分发事件记录 `executed`。需要测端到端延迟时，由播放器另行记录呈现时刻及其时间基准。

## 数据字段

| 对象 | 主要字段 |
| --- | --- |
| profile | `version: 2`、`engineVersion: 'dtw-custom-v2'`、`featureVersion: 'palm-path-20-v1'`、`trackerVersion: 'right-hand-v4'`、`coordinateSystem: 'body-right-v1'`、`participantId`、`revisionId`、`parentRevisionId`、`settings`、`gestures`、`history` |
| gestures 条目 | `gestureId`、`name`、`type: 'right_hand_dynamic'`、`actionId`、`positives`、`negatives`、`settings`。类别设置为 `threshold` 和 `negativeMargin` |
| 样例 | `sampleId`、`frames`、`confirmation`、`source`。来源记录 `runId`、类型、媒体起止及已知镜像状态，人工复核还保存对应意图或事件 |
| event | `gestureId`、`gestureName`、`actionId`、`tMs`、`startMs`、`endMs`、`positiveDistance`、`negativeDistance`、`scores`、`frames`。播放器可附加 `actionResult` |
| rejection | `tMs`、候选起止、`reason` 和可用的各类 `scores`。没有形成候选的静止帧不会逐条写拒绝 |
| run | `version: 2`、实际 `profile` 和版本信息、`runId`、`source`、`mode`、`frames`、`events`、`rejections`。`capture` 模式仅采集，`recognition` 模式运行识别 |

`event.tMs` 是系统作出判定时的媒体时间，通常晚于候选结尾 `endMs`。候选起止供人工复核使用。DTW 距离是特征差异值。导出必须保留运行时的实际参数与绑定。修改配置后要开启新一轮识别，为旧轮继续保留原快照。相同轨迹的离线回放可调用 `replay(frames, profile)`。

v1 接口由 `development-v41/recognizer-development.mjs` 提供，P01 配置及原有事件按 4.1 流程复现。v2 接受包含 `right-hand-v4` 坐标的旧运行轨迹以便重跑。两种配置在各自的入口导入。
