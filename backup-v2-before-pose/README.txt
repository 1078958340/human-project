Human Project｜自定义动态手势 v2
更新于 2026-11-23

新版可以示范注册少量右手动态轨迹手势，为每类保留正反例，并随时更改它绑定的功能。验证页可以查看识别日志和三张演示卡片。完整幻灯片播放器由成员2接入。

一、在 Windows 上启动新版

1. 保留整个交付目录，打开 01_code，双击 start-custom-gestures.cmd。保持服务窗口运行。
2. 用 Chrome 或 Edge 打开 http://localhost:8766/custom-gestures/index.html 。
3. 也可以在 01_code 目录的 PowerShell 运行 python -m http.server 8766 --bind 127.0.0.1 。若 Python 通过启动器安装，将 python 换成 py -3 。如果 8766 已被其他服务占用，将命令和网址中的端口同时改为 8767。

页面需要通过 localhost 的 HTTP 服务打开。MediaPipe 模型、脚本和 WASM 已随包提供。浏览器运行无需 npm、Node.js、GPU 或 API 密钥。Node.js 用于命令行检查和成员3接口。

二、录制个人示范和试用绑定

1. 在“手势配置”填写并保存参与者编号（本人暂用 P02）。添加两到三种容易区分的右手轨迹，例如向身体左侧滑动、向身体右侧滑动、向上移动。名称由你定义，识别类别来自你录的轨迹。
2. 选中类别，设置名称和功能后点“保存手势设置”。可选择下一页、上一页、暂停／恢复手势翻页，或暂不绑定。更改绑定保留类别 ID 及全部示范。
3. 点击“启动摄像头注册”，由使用者允许摄像头。检测到右手后点“录制正例”，只做一次动作，保持手掌完整入镜。动作结束后停约半秒，再点“结束示范”。每类分开录制 3–5 次。录完一条再把手移回起点。若界面提示两个类别过于接近，可调整动作后删掉相似示范再录。反例留给已确认会冒充该类别的动作。
4. 导出 v2 配置。完成注册后点击“停止”，再点“启动摄像头识别”。从第 1 页开始，翻页到边界时保留当前页。暂停期间仍识别动作并写日志，恢复手势仍可执行。每次动作后停住片刻，确认日志后再做下一次。
5. “分析原始录像”用于原始摄像头视频。仅当源文件已镜像时先勾选镜像选项。摄像头预览的 CSS 镜像与文件是否镜像是两个设置。“回放轨迹 JSON”用当前配置重算旧版或新版的 right-hand-v4 轨迹。配置与运行记录均需手动导出。不同运行在当前标签页分开保留，离开前按下拉框逐轮导出。

下一批 P02 材料先保留个人初始示范配置和注册 run，再保存校准试讲的原始视频、配套轨迹和意图标注。试讲应包括每类明确指令，也包括一段无指令的自然讲解。确认错误并冻结配置后，另录独立命令轮和自然轮。具体标注、校准与对照做法见 04_docs/成员3_校准与实验.md。

三、旧版 4.1 与 P01 基线

旧入口 http://localhost:8766/development-v41/index.html 。启动同一个本地服务后，加载 02_profiles/P01_calibrated-profile_v4.1-development.json，再分别回放 03_validation 中原始 command 和 natural 两份 run。每次运行独立，预期分别为 5 次触发和 1 次历史误触。P01 的初始配置为 5 正例，4.1 校准配置为 9 正例和 16 反例。

旧版配置继续由旧入口加载；v2 配置由新版加载。新版可重用旧 run 的标准化轨迹，使用自己的模板重新分析。原配置和验证资料仍记录 P01 的结果。03_validation 里的 screen.mp4 是浏览器录屏，可供核对，上传跟踪应使用摄像头原始录像。

四、检查与接口

在交付目录运行以下命令（需要 Node.js，本轮使用 v24.15.0）。

  node ./01_code/check-custom.mjs
  node ./01_code/check-development.mjs

合成轨迹用于验证识别逻辑、拒绝、重绑定、样例更新和同轨迹对照。真人注册体验、实际摄像头识别、误触率和正式实验待采集 P02 材料后完成。成员2的追踪、识别、播放器分发与格式见 04_docs/成员2_接口接入.md。

如遇摄像头权限问题，检查 Chrome 或 Edge 对当前 localhost 地址的授权。模型无法加载时，确认 01_code/vendor 目录完整并从 HTTP 地址启动。MANIFEST.sha256.json 记录当前交付文件的校验值。
