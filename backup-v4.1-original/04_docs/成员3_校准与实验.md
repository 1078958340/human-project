# 成员3：校准与实验

## 先复现最新结果

当前配置是02_profiles/P01_calibrated-profile_v4.1-development.json（9正例16反例）。03_validation中的两份run与两份screen为同一轮新实时检查，报告和summary保存核查结果。命令5/5，无额外触发；无意图自然活动1次误触。run的tMs是摄像头媒体时间，screen为浏览器录屏时间，不能直接等同。

浏览器先按README.txt启动、加载当前配置，点击“加载轨迹回放”，选择03_validation中的任一run，结果应为5次或1次。回放不需要启动摄像头。

可选命令行：在01_code目录运行（需要Node.js）：

```text
node replay-run.mjs "../02_profiles/P01_calibrated-profile_v4.1-development.json" "../03_validation/P01_livecheck-v41-command-run.json" "command-replay.json"
```

自然轮将command改为natural。脚本使用当前4.1引擎，拒绝覆盖已有输出，只复现事件，不自动判断人的翻页意图。

## 个人校准模块怎么接

当前识别器development-v41/recognizer-development.mjs导出prepareExample(raw, settings)、createRecognizer(profile)、replay(frames, profile)。正反例都是带时间戳的frames数组；数据格式和事件字段见成员2说明。

你负责：将人工意图与触发时间对齐；每个意图最多配对一个触发，其余算额外触发；列出漏触发与疑似误触；交由用户确认；将确认漏掉的命令通过prepareExample补为正例，将确认误触的事件frames补为反例；输出新profile给成员2重新加载。

新profile保持version:1、coordinateSystem:'body-right-v1'、mode:'calibrated'、positives、negatives、settings，并记录参与者、版本、来源片段及迭代记录。使用者的确认是必要信息，不能仅凭系统输出反推意图。

不要在本轮验收资料上改配置后覆盖原成绩。若将本轮误触用于改进，本轮即转为开发资料，新版本需要新的测试。

## 初始版和校准版如何公平比较

02_profiles/P01_initial-profile_v4.json保留P01原始5个示范，仅作为初始模板来源，其engineVersion元数据表示旧来源。精简包没有v4引擎；所有新比较均使用当前4.1识别器，不要把该文件直接当成旧引擎入口。

若比较模板校准的贡献，应先在内存或另存实验文件中构造以下对照：

```js
const baseline = {
  ...initialProfile,
  engineVersion:'dtw-v4.1-development',
  trackerVersion:'right-hand-v4',
  mode:'initial',
  settings:{...calibratedProfile.settings},
  negatives:[]
};
```

两组使用完全相同的frames、同一4.1引擎与同一settings，baseline保留原5个正例；另一组使用当前9正例16反例配置。该比较考察补充正例与反例的联合效果，不能单独归因于反例。如果需要区分正例/反例贡献，另设计固定正例的消融组，提前确定方案并保留版本。

上述构造是待实施的实验方法，本交付包尚未运行该对照，不代表已有成绩。保存实际使用的profile和事件，不能只根据文件名写initial/calibrated。五次命令的精确起止仍需人工标注，事件窗口startMs/endMs不等于真值。
